# Contributing

1. Open an issue describing the research or engineering decision being changed.
2. Keep production files under 300 lines and preserve one responsibility per module.
3. Add focused tests for behavior, boundary, or failure risks introduced by the change.
4. Run formatting, linting, type checking, tests, build, demo validation, and module
   validation.
5. Do not mark research guidance `APPROVED` without the documented human review.

Never add real participant data, copyrighted papers, access tokens, or fabricated
citations to fixtures.
